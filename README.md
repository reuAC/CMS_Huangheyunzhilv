# 黄河云之旅 - 旅游主题CMS系统

## 项目简介

黄河云之旅是一个用 Java Servlet 和 JSP 技术开发的旅游网站内容管理系统 (CMS)。它能方便地管理和展示黄河主题的旅游信息，当然您可以根据需要修改主题。系统有前台展示与后台管理两部分。

## 核心功能

*   **前台展示：**
    *   **动态首页：** 展示后台配置的景点、服务等。
    *   **主题游览页：** 如红色游、精品游等，页面内容（轮播图、卡片）由后台管理。
    *   **文章系统：** 发布图文并茂的旅游攻略和文化介绍，带标签分类。
    *   **内容搜索：** 用户可以按关键词搜索文章。
    *   **用户系统：** 支持用户注册、登录、退出。
    *   **导航系统：** 网站顶部和底部的导航菜单可在后台配置。
*   **后台管理 (`/admin/*`)：**
    *   **仪表盘：** 后台管理首页。
    *   **文章管理：** 增删改查文章，编辑标题、内容、作者、状态等。
    *   **页面元数据管理：** 管理各页面的SEO信息、大图展示区内容及特定版块的标题。
    *   **卡片管理：** 配置页面上各种图文卡片（标题、图片、链接等）。
    *   **用户权限：** 后台管理需登录才能访问。

## 技术栈

*   **后端：** Java (JDK 1.8+), Servlet API 4.0, JSP, JSTL
*   **前端：** HTML5, CSS3, JavaScript
*   **数据库：** MySQL 5.7+
*   **数据库连接池：** HikariCP
*   **日志：** SLF4J + Logback
*   **运行容器：** Apache Tomcat 9.0+

## 设计方案与理念

### 1. MVC 设计模式

项目采用 **MVC (模型-视图-控制器)** 模式开发，让代码结构更清晰，更容易维护和扩展。

*   **模型 (Model)：** 负责处理数据和业务规则。这包括：
    *   **数据对象 (POJO)：** 比如表示一篇文章或一个用户的信息。
    *   **数据访问 (DAO)：** 专门负责从数据库读取和写入数据。
    *   **业务逻辑 (Service)：** 处理具体的业务功能，比如用户登录验证、发布文章等。
*   **视图 (View)：** 用户能看到的界面。在本项目里，主要是 JSP 页面，它们负责把数据显示给用户。CSS 和 JavaScript 文件则用来美化页面和增加互动效果。
*   **控制器 (Controller)：** 接收用户的操作请求（比如点击一个链接），然后告诉模型部分去做相应处理，最后选择合适的视图把结果展示出来。在本项目里，Servlet 扮演了这个角色。

### 2. 分层架构

项目代码分为几层：管显示的界面层、管业务的逻辑层、管数据的存储层。每层各司其职，互不干扰，方便开发和维护。

### 3. 数据库驱动内容

网站的很多内容（文章、页面信息等）都存在数据库里。管理员可以通过后台直接修改这些内容，网站就能马上更新，不用改代码重新部署。

### 4. 模块化设计

*   不同功能由不同的 Servlet 处理。
*   页面头部、尾部等公共部分做成了可复用的 JSP 片段。
*   `BaseServlet` 把一些通用的 Servlet 代码抽出来，减少重复。

### 5. 安全性考量

*   **密码安全：** 用户密码经过特殊处理（加盐哈希）后再存到数据库，更安全。
*   **验证码：** 登录和注册时使用图形验证码，防止机器人。
*   **后台权限：** 后台管理页面需要登录才能访问。
*   **防SQL注入：** 用 `PreparedStatement` 操作数据库，能防止一种常见的网络攻击。

### 6. 可配置性

数据库连接、日志等信息都在配置文件里 (`db.properties`, `logback.xml`)，方便修改。

## 项目优点

1.  **结构清晰：** MVC模式让代码好懂、好维护。
2.  **低耦合：** 各部分代码联系不紧密，改一部分不容易影响其他部分。
3.  **内容管理方便：** 有后台，不懂技术也能更新网站。
4.  **容易扩展：** 因为结构好，加新功能或者改旧东西都比较方便。
5.  **代码重复少：** 公共部分抽出来共用。
6.  **数据库操作较安全高效：** 用了连接池和防SQL注入技术。
7.  **用户体验较好：** 前后台界面都考虑了用户操作的便捷性。
8.  **注重安全：** 有密码保护、验证码等基本安全措施。

## 优化方案说明

项目在设计时已考虑并实施了一些优化：

1.  **数据库连接池 (HikariCP)：** 用了 HikariCP 这个高性能的连接池，能让数据库访问更快。
2.  **SQL查询优化：** 用了 `PreparedStatement`，为关键字段建了索引，列表数据分页加载，这些都能提高查询效率。
3.  **前端资源优化：** CSS 按需加载，JS 延迟执行，这些能让网页打开更快。
4.  **Servlet与JSP优化：** 初始化操作只做一次，JSP里用标签代替Java代码，合理管理用户会话。
5.  **日志系统 (Logback)：** 记录程序运行情况，方便排查问题，并且可以控制记录的详细程度。
6.  **过滤器与监听器：** 统一处理编码防乱码，验证后台访问权限，管理应用启动和关闭时的资源。
7.  **事务管理：** 在一些关键的数据库操作中，确保了数据的一致性。

## 环境准备与运行

1.  **JDK：** Java 1.8 或更高版本。
2.  **Servlet 容器：** Tomcat 9.0 或更高版本。
3.  **数据库：** MySQL 5.7 或更高版本。
    *   创建一个数据库 (如 `huanghe_yunzhilv`)。
    *   运行项目根目录下的 `huanghe_yunzhilv.sql` 脚本，创建表并导入初始数据。

### 运行步骤：

1.  下载项目源码。
2.  **配置数据库：** 修改 `src/main/resources/db.properties` 文件，把里面的数据库地址 (`db.url`)、用户名 (`db.username`) 和密码 (`db.password`) 改成你自己的MySQL配置。
3.  **！！重要：图片资源！！**
    *   项目中的图片资源（位于 `/src/main/webapp/images/` 目录）没有直接放在代码包里。
    *   你需要从 **`https://pan.baidu.com/s/1MDe2i39KCrK5827kD6ktdw?pwd=sw8b`** 下载图片包。
    *   下载解压后，把所有图片放到项目中的 `/src/main/webapp/images/` 文件夹里。要保证图片路径和页面代码里用的一致，比如页面里写了 `images/banner.jpg`，那这个图片就应该在 `webapp/images/banner.jpg` 这个位置。
4.  **构建项目 (如果使用Maven/Gradle)：** 这一步会生成一个 `.war` 文件。
5.  **部署项目：** 把 `.war` 文件（或项目文件夹）部署到 Tomcat 的 `webapps` 目录下。
6.  启动 Tomcat 服务器。
7.  **访问项目：**
    *   浏览器访问 `http://localhost:8080/项目名/` (如果部署为ROOT，则为 `http://localhost:8080/`)。
    *   后台管理：`http://localhost:8080/项目名/admin/dashboard` 。

## 注意事项

*   确保MySQL服务已启动。
*   确保Tomcat端口（默认8080）没被占用。
*   第一次运行时，注意查看日志，确认数据库连接池是否成功启动。
